# Reflection

This Task Tracker extension was built iteratively with AI assistance rather than designed and coded in one pass. **ChatGPT** helped draft the user stories, Mini-ADRs, and the structured prompts later stored in `docs/prompts.md` and `docs/prompt-log.md`. The main coding tool was **Cursor Agent**, which applied those constrained prompts to `models.py`, `storage.py`, `main.py`, `business_rules.py`, tests, and `frontend/index.html`. The same prompts also steered **Copilot/Codex-style** frontend loops: plan small steps first, then implement one slice at a time (due-date field, overdue filter, tags chips, tag filter). AI helped most with boilerplate that had to stay consistent with an existing FastAPI style—adding fields, wiring query params, and expanding pytest without rewriting the baseline suite.

One clear win was the due-date and tags backend path: after Mini-ADRs locked “compute overdue dynamically” and “store tags as a per-task string list,” focused prompts produced approved checklist reviews and a growing green test suite (from a 19-test baseline to 47 tests). Generating fixtures and named tests for overdue filters and tag validation was much faster than writing them by hand, and the review prompts caught scope drift before it landed in the API.

AI also slowed the work. Adding the past-due business rule broke four overdue tests that still POSTed yesterday’s date. Separately, a temporary no-op in `validate_due_date_not_in_past` made two validation tests fail until the real check was restored. On the PATCH path, the first gating approach still failed when the edit form resubmitted an unchanged past due date; that needed my correction to validate only when the stored value actually changed. Frontend work similarly needed follow-ups: Save buried below the fold after more fields were added, no Clear control for the tag filter, and due-date errors showing at the top of the modal instead of under the field.

I changed the product at the requirements layer, not only in code. Early user stories left “valid due date” and tag rules vague; rewriting them (no past dates; tags alphanumeric, max 255) drove the business rule and `_validate_tag` validators. Mini-ADR review also rejected AI alternatives such as persisting an overdue flag or introducing a separate Tag entity. The pattern that worked was narrow prompts, run tests immediately, and treat AI output as a draft until stories, ADRs, and failing tests agreed.
