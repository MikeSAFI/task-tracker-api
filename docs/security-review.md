## SEC-06 Status on Create

**Decision:** Backlog; no safe one-line fix is justified until the product rule confirms that every new task must start in `ToDo`.

The behavior is confirmed: `create_task` does not call transition validation, and the create form sends its selected status. However, calling this a bypass assumes an unstated requirement that creation must begin at `ToDo`; the UI currently offers `ToDo`, `InProgress`, and `Done` at `frontend/index.html:833`-`836`.

**Minimal diff:** No diff proposed. Forcing `ToDo` would silently discard user input, while API-only rejection would leave the create form offering invalid choices.

**Before implementing a confirmed `ToDo`-only policy, check:**

- Update or disable the create-form options for `InProgress` and `Done` to avoid user-facing 422 responses.
- Expect direct API requests with `status: "InProgress"` or `"Done"` to change from 201 to 422.
- Add tests for successful `ToDo` creation and rejection of `InProgress` and `Done` creation.
- Preserve PATCH behavior: `ToDo` to `InProgress` to `Done` remains valid, while same-status and skipped transitions remain rejected.
- Document the applicable product decision: new tasks must start in `ToDo`, or creators may choose any valid initial status.
